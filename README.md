# MCDK IMAGE

面向 Minecraft / Bedrock 创作者的图像大模型素材助手。

它把图像模型接入到支持 MCP 的 LLM Agent 中，让你可以用自然语言生成、审查、修改和导出游戏素材，例如物品图标、方块贴图、UI 小图标、科幻武器、魔法道具等。

## 它适合做什么

- 生成 Minecraft 风格的像素画素材。
- 把大图压缩成更适合游戏使用的 `16x16` / `32x32` / `64x64` / `128x128` 贴图。
- 自动裁掉透明空白区域，让主体更居中。
- 先把图返回给 Agent 视觉自审，确认后再保存，避免无意义落盘。
- 对已有图片继续二次编辑，例如“让轮廓更清晰”“换成蓝色能量边缘”“减少噪点”。
- 复用上一次生成/编辑结果继续修改，不必每次重新生成。

## 推荐工作流

### 1. 先生成，不急着保存

你可以直接对 Agent 说：

> 生成一个 Minecraft 像素画物品图标：科幻风蓝色能量狼爪，只要一个物品，不要四宫格，不要文字，先返回给你自审。

Agent 会调用图像工具生成图片，并把结果保存在当前 MCP 进程缓存中。

### 2. 让 Agent 自审

生成后让 Agent 检查：

- 是否只有一个独立素材；
- 是否适合缩到 `32x32`；
- 轮廓是否清晰；
- 是否有噪点；
- 是否出现白底、伪透明棋盘格、文字、UI 边框或多个物品。

如果不满意，可以继续让 Agent 修改。

### 3. 连续编辑

例如：

> 保留这个狼爪主体，把蓝色能量边缘做得更亮，整体轮廓更清楚，仍然只保留一个图标。

这会基于上一张缓存图继续编辑，而不是重新从零生成。

### 4. 确认后保存

确认满意后再让 Agent 保存到你指定的完整路径。

> 保存到 `D:/Zero123/CPP/CMAKE/mcdk-image/outputs/wolf_claw_final.png`。

注意：本工具严格要求完整绝对路径，不接受相对路径。

## 像素尺寸建议

- `16x16`：简单、原版风、小型物品。
- `32x32`：多数物品图标最均衡，推荐默认目标。
- `64x64`：复杂武器、徽章、大型 UI 图标。
- `128x128`：高复杂度展示图，不建议普通游戏贴图默认使用。

实际生成通常先用大尺寸获得更完整的图，再压缩为游戏所需的小尺寸。

## 关于透明背景与可配置色幕

不要直接在提示词里要求模型“画透明背景”。部分模型会把“透明背景”“半透明”“棋盘格”理解成画面内容，从而画出白底、灰底或伪透明格子。

本工具支持两类透明方案：

1. **原生 PNG alpha**：通过模型参数请求透明输出；只有当网关和模型本身真的支持 alpha 时才可靠。
2. **色幕抠图**：引导模型把素材画在单一纯色背景上，再由本地后处理把这块纯色转成真正 alpha。当前更推荐这个方案。

色幕不一定必须是绿色。应根据素材主色调选择最不容易冲突的颜色：

- 避开素材主体的主色、发光边缘、半透明边缘、宝石/能量特效颜色。
- 选择画面中几乎不会自然出现的高饱和纯色。
- 蓝色水晶、蓝色魔法素材可考虑洋红或黄绿色；绿色植物、史莱姆、毒液素材可考虑洋红；火焰、金色、橙色素材可考虑青蓝；灰黑金属通常可使用亮绿或洋红。
- 色幕颜色必须和 `processing.chromaKey.r/g/b` 配置一致，否则后处理无法准确移除背景。

推荐让 Agent 使用 `processing.chromaKey.enabled=true`，并根据素材风格设置 `r/g/b`。工具会把所选 RGB 色幕自动补充进生成/编辑提示词。

## 使用时的自然语言提示建议

### 物品图标

> 生成一个 Minecraft 像素画物品图标：暗金色魔法钥匙，蓝色宝石镶嵌，单个物体，轮廓清晰，适合 `32x32`，不要文字，不要 UI，不要角色手持。

### 方块贴图

> 生成一个 Minecraft 方块贴图：深海遗迹风格的蓝绿色砖块，像素画，边缘可平铺，低噪声，适合 `16x16`。

### 科幻武器

> 生成一个 Minecraft 像素画武器图标：单个科幻能量匕首，青蓝发光边缘，深色金属核心，居中构图，适合 `32x32`，不要四宫格。

### 二次编辑

> 基于上一张图继续编辑：减少背景杂色，让主体更居中，增强外轮廓对比，保持单个物品图标。

## 常见问题

### 为什么不要一开始就保存？

因为图像模型可能生成多个物品、白底、伪透明、文字或噪声。先让 Agent 自审可以减少无效文件。

### 为什么保存必须写完整路径？

MCP 服务进程的工作目录不一定等于你的项目目录。使用完整路径可以避免图片保存到意外位置，也能正确支持中文路径。

### 为什么 `32x32` 最常用？

`16x16` 很有原版味，但复杂素材容易糊成一团；`32x32` 在轮廓清晰度和 Minecraft 风格之间比较平衡。

### 白色背景是不是 PNG 不支持透明？

不一定。PNG 只是容器格式，是否透明取决于图片是否真的包含 alpha 通道。如果模型或网关返回的是不透明白底 PNG，仍然会显示白色背景。

### 可以把已有图片继续改吗？

可以。你可以让 Agent 使用上一张缓存图继续编辑，也可以提供已有图片路径，让模型做二次编辑。

## MCP 配置示例

以下配置仅作为模板。不要把真实可执行文件路径、真实网关地址或真实 API Key 提交到仓库；请在你自己的 MCP 客户端配置中替换为本机路径和私有凭据。

```json
{
    "mcpServers": {
        "mcdk_image_stdio": {
            "command": "D:/path/to/mcdk-image-server.exe",
            "args": [],
            "env": {
            // 目前仅支持openai协议
            "MCDK_IMAGE_PROTOCOL": "openai",
            "MCDK_IMAGE_BASE_URL": "https://your-openai-compatible-endpoint.example/v1",
            "MCDK_IMAGE_API_KEY": "sk-your-api-key",
            "MCDK_IMAGE_DEFAULT_MODEL": "gpt-image-2",
            "MCDK_IMAGE_TIMEOUT_SECONDS": "400"
            },
            "timeout": 400,
            "disabled": false,
            "alwaysAllow": []
        }
    }
}
```

字段说明：

- `command`：本机编译出的 `mcdk-image-server` 可执行文件完整路径。
- `MCDK_IMAGE_PROTOCOL`：目前使用 OpenAI 兼容接口时填写 `openai`。
- `MCDK_IMAGE_BASE_URL`：OpenAI 兼容图像网关地址，通常以 `/v1` 结尾。
- `MCDK_IMAGE_API_KEY`：你的私有 API Key，不要提交到公开仓库。
- `MCDK_IMAGE_DEFAULT_MODEL`：默认图像模型，例如 `gpt-image-2`。
- `MCDK_IMAGE_TIMEOUT_SECONDS`：图像生成/编辑超时时间，建议给到 `400` 秒左右。

## 给部署者的说明

普通用户不需要理解工具参数或构建流程。

部署者只需要确保：

- MCP 服务已经接入你的 Agent；
- 图像模型网关可用；
- API Key 已通过环境变量配置；
- 保存路径使用完整绝对路径；
- 如果需要原生透明，网关和模型本身必须支持 alpha-capable PNG 输出；
- 如果模型不稳定支持原生透明，优先使用可配置色幕 + `processing.chromaKey` 后处理方案。

更详细的工程计划、接口设计和实现细节见 `plans/mcp-image-model-server-plan.md`。
